## Overview

NUERS is a Laravel 12 (PHP ^8.2) API plus a React 19 / TypeScript SPA (Vite 7, Tailwind 4, shadcn/Radix UI, react-router-dom 7) for a BIR (Philippine tax authority) e-invoicing / sales-reporting platform. It serves merchants, admins, BIR/RDO users, clients/consumers and a public developer portal. Laravel serves the SPA shell (`resources/views/app.blade.php`) via a catch-all route in `routes/web.php`; all `/api/*` routes live in `routes/api.php`.

## Commands

```bash
# Setup / dev
composer setup                 # install, .env, key, migrate, npm install + build
composer dev                   # php artisan serve + queue:listen + pail + vite (concurrently)
npm run dev                    # Vite only

# Frontend build / checks
npm run build                  # tsc -b && vite build && build:document (SSR document renderer -> bootstrap/ssr/document-renderer.mjs)
npm run build:static           # standalone static SPA to dist/ (vite.static.config.ts; API base from VITE_API_BASE_URL, default https://nuers.net/public)
npm run typecheck              # tsc --noEmit

# Backend tests (PHPUnit; sqlite :memory:, see phpunit.xml)
composer test                  # or: php artisan test
php artisan test --filter=MerchantWalletTest            # one test class
php artisan test tests/Feature/MerchantWalletTest.php --filter=test_method_name

# JS unit tests (node:test, import TS sources directly; no npm script)
node --test tests/js/                                   # all
node --test tests/js/rate-limit.test.mjs                # one file

vendor/bin/pint                # PHP formatting (Laravel Pint)
```

There is no JS linter configured.

## Architecture

- **Frontend (`src/`)**: `src/App.tsx` is a large central route table; pages are grouped by role/domain under `src/pages/*` (merchant, admin, super-admin, bir, rdo, client, developers, eis, ...). `@` aliases `src`. `src/lib/api-url.ts` is the API client wrapper (base URL, auth token via `session-store.ts`, 429 handling via `rate-limit.ts`); `src/lib/auth.tsx` holds auth context. Roles gate routes in `App.tsx`/layouts.
- **Backend (`app/`)**: thin controllers in `app/Http/Controllers/Api/`; business logic lives in `app/Services/*` (invoice calculation/sequencing, wallet, webhooks, MFA/TOTP, EIS delivery/readiness, BIR compliance, backup/recovery, tenant portability, etc.). `app/Contracts/EisProvider.php` with `Services/Eis/BlockedProvider.php` — the official BIR/EIS transport is intentionally **blocked**; activation flags in `config/bir_compliance.php` stay false. Don't enable or fabricate submissions/approvals.
- **Middleware** (`app/Http/Middleware`): `ApiBoundary` / `IntegrationApiResponse` (merchant integration API contract and sandbox/production isolation), `ScopedThrottleRequests` (custom throttle keys, e.g. `throttle:5,1,registration-email:`), `SecurityHeaders`.
- **Integration API**: merchant systems post transactions through the versioned ingestion contract (`docs/integrations/merchant-ingestion-1.md`, `docs/NUERS_TRANSACTION_API_INTEGRATION.md`); sandbox vs. production data are isolated. Signed webhooks are delivered by `php artisan` command `DeliverMerchantWebhooks`.
- **PDF/documents**: `scripts/document-renderer.tsx` is bundled by esbuild into `bootstrap/ssr/document-renderer.mjs` and used server-side by `app/Services/DocumentPdf.php` (config in `config/document_pdf.php`) — rebuild with `npm run build:document` after changing frontend document components.
- **Data**: MySQL locally/live (tests use sqlite in memory); migrations in `database/migrations`, extra SQL in `database/sql`. Migrations are additive and reviewed — existing financial data (transactions, invoices) must be preserved; back up before migrating. `supabase/` holds an edge function and migrations for a secondary integration (`src/lib/supabase.ts`).
- **Reference data** is generated by `scripts/build-*.py` (registration geography/industries, RDO localities, developer catalog) into `resources/data` and similar; regenerate rather than hand-edit.

## Deployment / environment notes

- `deployment/LOCAL_LIVE_DATABASE_WORKFLOW.md` documents the local-vs-live (Plesk, nuers.net) DB workflow, backups and the current schema state; read it before touching migrations or data. Local app runs at http://localhost:8001 using an isolated MySQL on 127.0.0.1:3307 started by `.local/start.sh` (`.local/` is gitignored and may not exist).
- `dist/` is committed (static build output for hosting); `.htaccess` at repo root supports hosting the repo root as the web root, with `/public/...` aliases in `routes/web.php`.
- Audit and remediation write-ups are in `docs/audits/` and `docs/knowledge/`; `deployment/` has env examples and reports.
- Don't perform live deployments or send external BIR/webhook messages without explicit instruction.
