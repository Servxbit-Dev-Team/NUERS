## Support widget and administrator inbox

Public widget: `src/components/support/chat.tsx`; admin inbox: `/super-admin/support`, also linked from Client Support & SLA. Both are branded to match NUERS. The visitor can provide optional name/email, topic and message. Messages are persisted in the local database, not sent automatically by email/SMS. Administrator replies appear in the visitor widget. The inbox includes search across contact/topic/message text, status and priority filters, unread-only filter, counts, pagination, full history through Load earlier messages, assignment to admin users, open/pending/resolved states and normal/high/urgent priority. Visitor messages reopen resolved conversations. Agent replies mark them pending; explicit resolution is an admin action.

Persistence: migration `2026_10_15_000008_create_support_chat_tables.php` adds `support_conversations`, `support_messages`, `support_events`. Messages use per-conversation request UUIDs for retry idempotency. Creation uses a client-generated UUID and cryptographically random token; the raw token is held in browser local storage and only its hash is stored in the database. Every visitor lookup/read/send is scoped to that conversation and token. Tokens expire after 90 days. Admin list/history/reply/triage endpoints validate an authenticated admin or super_admin profile. Public responses omit contact email, internal sender IDs and token hashes. Admin responses never return token hashes. Request validation and route rate limits constrain body size and submission rates. Revision checks prevent silent concurrent triage overwrites. Assignment/status changes and message events create a separate server audit history.

Visitor open threads/admin inboxes poll every 5 seconds while the page is visible; a closed widget with a known session checks for unread agent messages every 15 seconds. This is polling, not a claim of WebSocket delivery, 24/7 staffing or an SLA. Read counts are shared by the admin team, not per-agent. All message text is rendered as plain text. Pagination allows older history without jumping to the bottom. Dates are returned with the configured timezone offset. No attachments, internal notes, automatic notifications, escalations or purge schedule are claimed. Starting a new browser conversation removes the local access link and leaves server history intact; retention/deletion requests go to the supplied privacy contact.
