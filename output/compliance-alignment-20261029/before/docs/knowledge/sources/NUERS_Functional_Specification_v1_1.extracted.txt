1. Universal interaction standards

data without warning.
Topbar: Search, breadcrumbs, notifications, profile, sign-out, environment and connection status. Notifications open an
accessible drawer.

cancel.

and audit event.
Security: Role-based access control, MFA for privileged actions, tenant isolation, encryption, rate limiting and
tamper-evident audit events.

4. BIR EIS operational lifecycle
1. Intake — Receive authorized source record with tenant, branch, source ID and idempotency key.
2. Validate — Verify required fields, document type, totals, duplicate risk and taxpayer authorization.
3. Issue — Commit canonical document and immutable audit event; generate PDF separately.
4. Queue — Persist transmission outbox and due time; enqueue durable job.
5. Transmit — Use verified BIR endpoint and approved credentials; record attempts.
6. Respond — Match acknowledgment by official reference; transport success is not necessarily acceptance.
7. Reconcile — Compare issued, sent, acknowledged and rejected sets; open exceptions.
8. Preserve — Back up, export, audit, retain and allow lawful taxpayer access.
5. Critical QA acceptance scenarios
• A repeated API request with the same idempotency key does not create a second issued invoice.
• A BIR timeout with unknown acceptance outcome is investigated before a retry; duplicates are prevented.
• A failed web server does not cause loss of acknowledged transactions.
• A database promotion does not result in two simultaneous writable primaries.
• A storage node failure retains readable invoice objects under tested replication conditions.
• An unauthorized user cannot open tenant-specific records by changing URL or API parameters.
• Exports and document corrections create auditable events and preserve original records.
• All modal controls are keyboard accessible, clearly labeled and handle errors.
